## Description

BugDesk opens the outline editor (`createOutlineEditor`) in a modal
ManagedWindow. Clicking "Add a step" opens the step picker BEHIND that window,
so it cannot be used.

`.twm-flow-popover` (the step picker, the value picker and the step menus,
`src/flow/kit/dom.js` `openPopover`) and `.twm-flow-outline__ghost` (the
grip drag) use `z-index: var(--z-popover)`, 200. Managed windows stack from
6000 to 6999 (`managed_window.js` BASE/MAX_Z_INDEX). The context menu already
sits above them (10050). Any flow editor hosted in a window has the bug.

Seen from BugDesk STORY-0028 (`../bugdesk/backlog/STORY-0028.md`).

## Comments

### 2026-10-14T06:58Z · norman_agent (status: investigation -> testing)

Fixed in f127f1a and released as flexdesk 0.11.1 (001f676).

- **Cause:** `.twm-flow-popover` (the step picker, the value picker and the
  step menus) and `.twm-flow-outline__ghost` sat at `--z-popover`, 200. Managed
  windows stack from 6000 to 6999, so any flow editor hosted in a window opened
  its menus behind it.
- **Fix:** a new token, `--z-over-windows: 7100`, above the windows and below
  the toasts. Both rules use it, in `css/flexdesk.css` and in `base.css`'s
  mirror.
- **Test:** `tests/flow_popover_layer.test.mjs` reads the z-indexes from the
  sheets and the window range from `managed_window.js`. Without the fix it
  fails 7 times; with it, it passes.
- **Checked in BugDesk:** in its "Flow — …" window in Edge, "Add a step" had
  opened a popover at z-index 200 that was not on top. With the fixed sheets
  it opens at 7100, in front.
- **Release:** built from a clean worktree at f127f1a. The full suite ran
  there: 86 suites, green, none skipped.
- **One thing to know:** my first local commit of this fix took
  `css/flexdesk.css` whole, including another session's uncommitted STORY-0016
  CSS. Their warning caught it before anything was pushed or built. I rewrote
  the commit with my lines only, and their working tree stayed as it was.
