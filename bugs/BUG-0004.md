## Description

EventBus.off(target) (src/core/event_bus.js:84-88) accepts an id or handle; a string removes nothing. Sites: src/tiling/page_factory.js:122/127, src/tiling/shell.js:243/272, src/ui/components/notification_history.js:111-112.

## Steps to reproduce
1. createShell({eventBus}), shell.dispose(), build a second shell on the same bus; check listenerCount('wm:changed').
2. createPageFactories with refreshOn, mount and tear down a tab, emit the refresh event.

## Expected
Teardown removes listeners; counts return to the pre-subscribe value.

## Actual
The disposed shell's syncChrome keeps running against its dead wm; disposed tabs still get refresh(); each NotificationHistory leaves a listener.

Related EcoSim records: EcoSim STORY-0018 (`../EcoSim/backlog/STORY-0018.md`); EcoSim STORY-0011 (`../EcoSim/backlog/STORY-0011.md`); EcoSim STORY-0034 (`../EcoSim/backlog/STORY-0034.md`).

### 2026-10-17T16:11Z · norman_agent (status: investigation -> testing)

Fixed and landed on main. All three sites now unsubscribe by calling `dispose()` on the handle `on()` returned, instead of `eventBus.off(name, fn)`, which removed nothing:

- src/tiling/page_factory.js: the refreshOn handles are kept and disposed on tab teardown (`handle?.dispose?.()`).
- src/tiling/shell.js: `shell.dispose()` disposes the `wm:changed` chrome subscription, so a disposed shell's syncChrome no longer runs.
- src/ui/components/notification_history.js: the subscription handle is disposed on dispose.
- New test tests/bus_listener_teardown.test.mjs checks that each site adds a listener on subscribe (`before + 1`) and that teardown brings `listenerCount` back to the value before the subscribe.
