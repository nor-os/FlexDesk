What was built (src/help/help_modal.js):
- A help topic with two or more h1-h6 headings, markdown or html, now gets a numbered, scroll-spied contents list between the breadcrumb and the article. It reuses the existing createDocumentOutline component.
- The list points at the heading elements themselves, so the provider's markup gets no ids.
- The list is disposed when you go to the index, search, open another topic or close the modal. A topic that finishes loading after the modal was closed is ignored.
- The header comment now describes this behaviour instead of the old promise.
- Markdown rendering (`topic.markdown`) and the HelpTopic typedef saying that `topic.html` is pre-rendered, TRUSTED HTML inserted verbatim were already on main (help_registry.js:24-27, README).
- The README gains a paragraph on the contents list, css/base.css and css/flexdesk.css get the `.help-content__toc` styles, and tests/help_modal_css.test.mjs needed a second heading in its fixture.
- No public API change and no new exports.
