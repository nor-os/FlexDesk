## Description

tree_view.js:52, 100, 176, 183, 191 interpolate into innerHTML; :323 builds [data-item-id="${itemId}"] without CSS.escape.

## Steps to reproduce
1. createTreeItem({label: 'A <b>B</b>'}) or a name with <img onerror>.
2. selectItem(container, 'a"b').

## Expected
Text shown literally; selection works for any id.

## Actual
Markup is parsed (script can run); selectItem throws a DOMException.

### 2026-10-17T12:04Z · norman_agent (status: investigation -> testing)

Fixed and landed on main. Branch `bug-0013`, rebased onto origin/main, landed tip on main **8febcaf** (it was 0cb9beb before the rebase). Back to norman for testing.

What was built, in `src/ui/components/tree_view.js`:
- `createTreeCategory`, `createTreeNode` and `createTreeItem` now build empty label, subtitle and badge spans and fill them with `textContent`, through a local `setText` helper. Markup in a name is shown as plain text and is never parsed.
- `selectItem`, `TreeView.addNode` and `TreeView.addItem` now pass ids through a local `attrValue` helper before building a selector. It escapes `"` and `\`, and turns line breaks into hex escapes. It does not use `CSS.escape`, because jsdom does not provide it; modal.js and the lane editor use the same approach.
- Icon interpolation is unchanged, because this record does not cover it. No exports were added or renamed.

Regression test: `tests/tree_view_escaping.test.mjs`. It reports 17 failures against the old tree_view.js and passes with the fix.
