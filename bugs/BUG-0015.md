### 2026-10-17T14:57Z · norman_agent (status: investigation -> testing)

BUG-0015 is fixed and landed on main: branch `bug-0015`, tip 6f24a26 (the rebased c237f20). The fix is on main now.

What changed: createDetailHeader used to emit the unprefixed classes `detail-header__badge` and `detail-header__btn--<variant>`, and FlexDesk's CSS has no rule for either one.
- Badges are now `.twm-detail-header__badge`, a pill built from tokens in css/flexdesk.css and mirrored in css/base.css. The badge icon is `.twm-detail-header__badge-icon`.
- Action buttons reuse the existing `.twm-btn` look. 'primary' adds `.twm-btn--primary`, 'danger' adds `.twm-btn--danger`, and 'secondary' is the plain button. Each button keeps `.twm-detail-header__btn` and `.twm-detail-header__btn--<variant>`. Its icon and label are `.twm-btn__glyph` and `.twm-btn__label`. An action without an icon no longer gets an empty icon span.
- The stale 'moved to components/controls.css' comment is removed, and README Styling notes the class change.

The emitted class names do change. That is the defect this record names, and the README already promises that every class is `twm-` prefixed. Outside FlexDesk, these names appear only in bugdesk's own controls.css, and bugdesk does not call createDetailHeader.

Criteria verified (this record has no checkbox list, so they are listed here):
- Steps to reproduce no longer reproduce. createDetailHeader with badges and primary/danger actions, using only FlexDesk CSS, gives themed pills and button variants you can tell apart.
- Regression test: tests/detail_header_styles.test.mjs. It passes, and it fails 53 assertions against the unfixed code.

Tests: after rebasing onto origin/main, `node tests/run.mjs` gives FLEXDESK TESTS: GREEN, 109 suites, no SKIPPED lines. `node build.mjs` succeeded, and dist/ was reverted afterwards.
App check: not done. The app was not launched for this handback; the fix is checked by the DOM/CSS regression suite only.

Separately, outside this bug: css/flexdesk.css's `.twm-detail-header__name .twm-node-edit-input` rule has `background: var(--surface-1));` with an extra `)`, so the browser ignores that declaration. Worth a record of its own.
