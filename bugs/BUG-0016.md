### 2026-10-17T11:01Z · norman_agent (status: investigation -> testing)

Fixed and landed on main. Back to norman for testing.

What was built (src/ui/components/sortable_list.js), two causes:
1. The itemSelector given to DragReorder ('.sortable-list__row') did not match the class the rows get ('twm-sortable-list__row'), so no row was ever draggable. Both now come from one ROW_CLASS / ROW_SELECTOR constant.
2. A second fault the description does not mention: the handle check read dragstart's target, but a browser fires dragstart at the draggable row, never at the handle inside it, so it would have stayed broken after the selector fix. The list now records on mousedown whether the press landed on the handle; the dragstart check reads and clears that flag.
mountAttributeListEditor gets the fix through SortableList. No public API, exports or entry files changed.

Criteria verified (this record has no checkbox list, so recorded here):
- Steps to reproduce no longer reproduce: mount a SortableList with 3 items and drag a row by its handle; the row moves and onChange fires. Verified by tests/sortable_list_reorder.test.mjs.
- Regression test: tests/sortable_list_reorder.test.mjs (16 assertions). It fires dragstart at the row, as browsers do, so it fails against the old handle check as well as the old selector. It also covers a drag that starts outside the handle (cancelled, no onChange) and mountAttributeListEditor reordering.

Branch bug-0016, rebased onto origin/main and landed on main as 5a63b72 (fast-forward). The branch is kept on origin.
