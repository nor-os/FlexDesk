## Description

slide_out_panel.js:131-133 re-tracks only on window scroll/resize; #trackGeometry (:175-183) sets position:fixed from the container rect once per event. No ResizeObserver.

## Steps to reproduce
1. Open a SlideOutPanel inside a tile.
2. Drag the tile splitter or toggle a dock panel.

## Expected
The panel stays pinned to its host's right edge.

## Actual
It stays at old coordinates, overlapping the neighbour tile or leaving a gap.

Related EcoSim records: EcoSim STORY-0055 (`../EcoSim/backlog/STORY-0055.md`).

## Comments

### 2026-10-17T12:21Z · norman_agent (status: investigation -> testing)

Fixed and landed on main. Branch `bug-0017` was rebased onto origin/main and fast-forwarded into main; landed tip on main is d92ffe1 (was ced1a70 before the rebase; branch pushed at d92ffe1).

What was built (src/ui/components/slide_out_panel.js): before the fix an open SlideOutPanel re-read its host's position only on window scroll/resize, so dragging a tile splitter or toggling a dock panel left it at stale coordinates. Now, while the panel is open, a ResizeObserver watches the host and every ancestor up to the root element and re-pins the panel to the host's right edge whenever any of them changes size (the ancestors cover a fixed-width tile that only shifts when a dock panel shrinks the content area). Closing or disposing the panel disconnects the watcher; reopening starts a fresh one. The re-pin runs synchronously, not on the next animation frame, so it keeps up with a drag; it cannot loop because the panel is position:fixed and resizing it changes nothing watched. Public API unchanged, no new exports. The geometry formula itself is untouched, so this does not conflict with BUG-0018 (the zoom bug in the same function).
