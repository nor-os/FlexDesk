## Description

#trackGeometry copies getBoundingClientRect (already zoomed) into a fixed element inside a `zoom: var(--twm-zoom)` subtree (css/base.css:5224-5225), so lengths scale twice. Not yet confirmed in a running WebView2.

## Steps to reproduce
1. Mount a SlideOutPanel in a tile, set zoom to 150%, open it.

## Expected
Flush with the host's right edge at the host's height.

## Actual
Shifted right and down by about the zoom factor, often off-screen; too small at 50%.

Related EcoSim records: EcoSim STORY-0055 (`../EcoSim/backlog/STORY-0055.md`).

Filed from the EcoSim -> FlexDesk 0.16 migration analysis (2026-10-17).

### 2026-10-17T13:07Z · norman_agent (status: investigation -> testing)

Fixed and landed on main. Branch `bug-0018` @ `3b48a04`, which is also the tip of main (fast-forward).

What was built: `SlideOutPanel`'s `#trackGeometry` (`src/ui/components/slide_out_panel.js`) now converts the host's `getBoundingClientRect()`, which is in screen pixels, to CSS pixels by dividing by the panel's effective zoom (`currentCSSZoom || 1`, the same idiom DataTable uses). The width it subtracts is now the panel's laid-out width (`offsetWidth || width`, because `min-width: 400px` can make the panel wider than requested), scaled by that zoom. Rounding happens in screen pixels, so at 100% the output is exactly the same as before. No exports or public API changed.

Landing note: this rebased onto BUG-0017's host-resize tracking (`#observeHost`, ResizeObserver). The only conflict was the doc comment on `#trackGeometry`, and both sides' text is kept. The zoom division and the `offsetWidth` width from this branch are unchanged. After the rebase, the new suite failed because jsdom has no ResizeObserver and an open panel now creates one. The suite now installs a no-op ResizeObserver; host resizes are covered by `slide_out_host_resize.test.mjs`.

Definition of done (the record has no acceptance-criteria section, so these come from the bug rule):

- [x] Regression test exists: `tests/slide_out_panel_zoom.test.mjs`. It passes with the fix and fails 5 assertions without it.

These ran on the rebased tree. The final rebase picked up only a `bugs/BUG-0027.md` record commit, so the code tree is identical to the one tested.
