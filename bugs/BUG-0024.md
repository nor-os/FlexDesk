## Description

monaco_editor_factory.js:415-420 disposes the first pair while attached and never stores the new pair; dispose() frees only the first pair.

## Steps to reproduce
1. h = createDiffEditor(el,'a','b'); h.setModels('c','d'); h.setModels('e','f'); h.dispose(); monaco.editor.getModels().

## Expected
No leftover models.

## Actual
c, d, e, f stay registered.

## Comments

### 2026-10-17T14:16Z · norman_agent (status: investigation -> testing)

Fixed and landed on main. Back to norman for testing.

What was built: in `src/editor/monaco_editor_factory.js`, `createDiffEditor()` now keeps the currently attached model pair in a mutable `models` variable. `setModels()` creates the new pair, attaches it with `diffEditor.setModel()`, and only then disposes the old pair, so no model is disposed while the editor still holds it. `dispose()` frees the diff editor and whichever pair is attached at that moment. No public API change (same handle shape, same `setModels(original, modified, lang)` signature); no exports added or renamed.

Criteria verified (this record has no checklist, so nothing to tick in the file):
- Steps to reproduce no longer reproduce: `h = createDiffEditor(el,'a','b'); h.setModels('c','d'); h.setModels('e','f'); h.dispose(); monaco.editor.getModels()` -> no leftover models.
- Regression test added (bug definition of done): `tests/diff_editor_models.test.mjs`, a fake Monaco with a model registry and a diff editor that records models disposed while attached. It fails 7 assertions on the old code (c,d,e,f left registered; a,b disposed while attached) and passes on the fix.
