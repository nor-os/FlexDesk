## Description

package.json exports have ./css and ./css/tokens but no reset; an exports map blocks the deep path too.

## Steps to reproduce
1. `import 'flexdesk/css/reset'` or require.resolve it.

## Expected
Resolves to dist/reset.css as in the documented three-file contract.

## Actual
ERR_PACKAGE_PATH_NOT_EXPORTED.

Related EcoSim records: EcoSim STORY-0017 (`../EcoSim/backlog/STORY-0017.md`).

Filed from the EcoSim -> FlexDesk 0.16 migration analysis (2026-10-17).

## Comments

### 2026-10-17T11:39Z · norman_agent (status: investigation -> testing)

Fixed on branch `bug-0027` @ `dfc89a4`, not yet on main.

- package.json: added `"./css/reset": "./dist/reset.css"` to `exports`, so
  `flexdesk/css/reset` resolves under `import` and `require` instead of
  failing with ERR_PACKAGE_PATH_NOT_EXPORTED.
- README Styling: the contract table now has a Specifier and a Resolves-to
  column taken from the exports map. `flexdesk/css/tokens` is documented as
  resolving to the source `css/tokens.css`, because that is what the map says.
  It does not resolve to `dist/tokens.css`. The two are identical in a release
  but can differ on a working checkout. I filed that as BUG-0030 rather than
  repointing an existing public specifier here.
- tests/css_exports.test.mjs: §1 pins reset to dist/reset.css. §2 pins
  `flexdesk/css` to dist/flexdesk.css and `flexdesk/css/tokens` to
  css/tokens.css. §3 checks that every CSS export exists and is under `files`.
  §4 parses the README table and checks each row's target against the real
  resolution. I mutation-checked it: the README row put back to dist/tokens.css
  fails §4, and the export repointed to dist/ fails §2 and §4.

`node tests/run.mjs`: GREEN, 98 suites, none skipped. `node build.mjs`
succeeds (dist/ not committed).

To verify: `node -e "console.log(require.resolve('flexdesk/css/reset'))"` from
the branch checkout prints .../dist/reset.css.
