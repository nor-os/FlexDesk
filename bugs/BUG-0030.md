## Description

package.json maps `./css` and `./css/reset` (BUG-0027) to `dist/`, but
`./css/tokens` to the source `./css/tokens.css`. The README's Styling section
names `dist/tokens.css` as the contract file. The two are byte-identical in a
release, because dist/ is rebuilt only in the release commit, but on a working
checkout (or a git dependency) they can differ, so `flexdesk/css/tokens` does
not serve the file the contract documents.

Found while fixing BUG-0027; the README on branch bug-0027 now states the real
mapping (`flexdesk/css/tokens` -> `css/tokens.css`) and tests/css_exports.test.mjs
pins it, so fixing this means changing the exports target, the README row and
that test together. Repointing an existing public specifier is the owner's call.

## Steps to reproduce
1. `node -e "console.log(require.resolve('flexdesk/css/tokens'))"` from the package root.

## Expected
Resolves to dist/tokens.css, like the other two contract stylesheets.

## Actual
Resolves to css/tokens.css.

## Comments

### 2026-10-26T10:58Z · norman_agent (status: investigation -> testing)

Fixed on main in c66850e (dist rebuilt in 31de892). Not released: package.json is still 0.17.13.

`package.json` now maps `./css/tokens` to `./dist/tokens.css`, like `./css` and `./css/reset`. Before, `require.resolve('flexdesk/css/tokens')` from the package root printed `css/tokens.css`; now it prints `dist/tokens.css`, and `import.meta.resolve` agrees. `dist/tokens.css` is byte-identical to `css/tokens.css` after a build, so an installed release serves the same bytes as before; only a checkout or git dependency whose source has moved past the last dist rebuild sees a different file, and it is now the documented one.

The Styling table and paragraph in `docs/concepts/styling.md` are corrected in place (no new section; the mapping was already documented there and was wrong). `tests/css_exports.test.mjs` moves with it and gains two checks: every `./css*` export must be a built copy under `dist/`, and the docs' contract-file and resolves-to columns must name the same file.

For the release notes: this repoints a public specifier, so the changelog should call it a change in what a specifier resolves to, not an additive change, even though the bytes are the same in a release.

Three independent reviewers (correctness, test honesty, scope and docs) found no blockers. The full suite (210 suites, none skipped) passes on the merged tree.
