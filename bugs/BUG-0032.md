## Description

Found while releasing 0.17.0 (STORY-0069): package.json's exports map gives each entry a `development` condition pointing at the root entry files (`./core.js`, `./host.js`, `./wm.js`, ...). Those files are not in "files", so the published package does not contain them. Present before 0.17.0 too.

## Steps to reproduce

1. `npm install flexdesk@0.17.0` in an empty directory.
2. Resolve `flexdesk/core` with the `development` condition (e.g. `node --conditions=development -e "import('flexdesk/core')"`).

## Expected

The import resolves to a file the package ships. Either the root entry files are shipped, or the `development` condition is removed from the exports map; a test checks that every exports-map target exists in `npm pack --dry-run`'s file list. Ships in 0.17.1 (STORY-0097).

## Comments

### 2026-10-21T10:10Z · norman_agent (status: investigation -> testing)

Fixed and landed on main @ 633e1a0 (fix commit 79917cf, first pushed on branch bug-0032). Back to norman for testing.

What was built: the nine root entry barrels (core.js, host.js, wm.js, widgets.js, charts.js, tiles.js, editor.js, canvas.js, flow.js) are added to package.json "files", so the `development` condition now resolves to files the package ships. These barrels only re-export src/, which was already packed. The exports map is unchanged, so no public API changed. I chose shipping the barrels over removing the condition (the record allows either): removing it would break tests/flow_kit_scaffold.test.mjs, which pins `development: './canvas.js'` / `'./flow.js'`, and the demos load the barrels directly.

Note: `import` precedes `development` in every entry, so an ES import resolves to dist/ even under --conditions=development; the repro command as written always reached dist/core.js. Only `require.resolve` under the development condition (or a resolver skipping `import`) hit the missing ./core.js. That ordering is unchanged and now pinned by the test.

Expected-behaviour points verified: the import resolves to a shipped file (root entry files shipped); a test checks every exports-map target exists in `npm pack --dry-run`'s file list; ships in 0.17.1 (STORY-0097), documented in README.md Build section under "The `development` condition resolves in the installed package (0.17.1)"; done = repro no longer reproduces + a regression test that fails without the fix.

Regression test: tests/exports_packed.test.mjs runs `npm pack --dry-run --json` and checks every target of every condition is in the tarball and on disk, that each development barrel re-exports only packed ./src/ files, and that ES import still resolves every entry to dist/ under --conditions=development.

Tests run: `node tests/run.mjs` (Linux, node v18.19.1) "FLEXDESK TESTS: GREEN — 183 suite(s)", exit 0, no SKIPPED lines, "exports packed: OK"; `node build.mjs` exit 0 with dist/ identical to committed and no untracked chunks; tests/flow_kit_scaffold.test.mjs and tests/css_exports.test.mjs pass standalone.
