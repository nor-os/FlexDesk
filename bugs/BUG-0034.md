## Description

Found by EcoSim STORY-0037 (`../EcoSim/backlog/STORY-0037.md`) in the real app on FlexDesk 0.17.2. NotificationHistory updates its badge only from bus events ('toast:show', 'notification:show', 'log:entry', ...; dist/widgets.js around 3082-3093). NotificationCenter.show(), warn(), error() and info() record their own history but emit nothing (around 6793 and 7004), so a toast raised through the API never raises the bell's unread badge. A single toast raised as a bus event is recorded twice (history.length goes 1 -> 3 for two warns). norman decided on 2026-10-22 that this is fixed in FlexDesk, generically, and shipped as 0.17.3.

## Steps to reproduce

1. Mount NotificationCenter and NotificationHistory on one bus.
2. Call `NotificationCenter.warn('x')`: the badge stays hidden while the history gains an entry.
3. Emit one 'toast:show' warn on the bus: the history gains two entries.

## Expected

NotificationHistory follows NotificationCenter's own history: NotificationCenter tells its subscribers when it records an entry, and every toast raised through either path counts exactly once in the history and the unread badge. A regression test fails on today's main for both paths. Documented in a README section headed "(0.17.3)".

### 2026-10-22T19:15Z · norman_agent (status: investigation -> testing)

Fixed on branch `bug-0034` (commits f57a09c, tip 6ce0fb9), pushed to origin/bug-0034, up to date with origin/main; not yet on main. Ships with FlexDesk 0.17.3 (STORY-0104). After that, EcoSim STORY-0037 takes the 0.17.3 lock and adds its own test that a direct NotificationCenter.warn() raises the badge.

Root causes: (1) NotificationHistory raised its badge only on bus events, and the API (show/warn/error/info/success) emits nothing. (2) NotificationCenter pushed a second `{...toast, dismissed, reason}` entry into `history` whenever a toast left (timeout, x, overflow), so one toast appeared twice.

What was built:
- `src/ui/notification_center.js`: new method `subscribe(fn)` calling `fn(entry, center)` once per entry added to `history` (not for skipHistory toasts or dismissals), returns an unsubscribe; a throwing listener is logged and others still run; dispose() drops listeners. A dismissal now marks the toast's own entry (`dismissed: true`, `reason`) instead of adding one.
- `src/ui/components/notification_history.js`: the bell subscribes to the center instead of the bus; each recorded entry counts as one unread until the popover opens (also past the history limit), the badge never exceeds what the popover lists; unmount() unsubscribes; `lastSeenCount` replaced by `unreadCount`.
- README section "### One toast, one history entry, one unread (0.17.3)", noting the bell no longer watches the bus for toasts.
- No entry-file exports changed; CHANGELOG/version left to STORY-0104.
- Behaviour change: NotificationHistory's `notificationCenter` must now be a NotificationCenter (or have `history` and `subscribe`). tests/notification_bell.test.mjs §1 and tests/bus_listener_teardown.test.mjs §3 updated accordingly.

Verified (the Expected/repro points):
- Repro step 2: NotificationCenter.warn('x') with both mounted on one bus raises the unread badge.
- Repro step 3: one 'toast:show' warn adds exactly one history entry.
- NotificationCenter tells subscribers when it records an entry; NotificationHistory follows its history.
- Every toast through either path counts exactly once in history and badge.
- Regression test tests/notification_history_follows_center.test.mjs fails on origin/main sources for both paths and passes on the branch.
- Documented in a README section headed "(0.17.3)".

Tests: `node tests/run.mjs` (Linux node) GREEN, 197 suites, 0 skipped (second full run; the first failed only bus_listener_teardown §3, fixed in 6ce0fb9). `node build.mjs` succeeded; dist/ restored afterwards.
