## Description

Found by EcoSim BUG-0028 (`../EcoSim/bugs/BUG-0028.md`) on FlexDesk 0.17.4. When an editor gets focus, Monaco's WordHighlighter calls `runDelayer.trigger()` (a 50 ms Delayer) and never catches the promise. If the editor is disposed within those 50 ms, `Delayer.dispose() -> cancel()` rejects that promise with a CancellationError (name and message 'Canceled'), and nothing handles it. The browser then logs an uncaught 'Canceled: Canceled at i.cancel (editor.main.js) at i.dispose ... at g.clear ... at g.dispose'. `safeDispose` in src/editor/monaco_editor_factory.js says it swallows this benign error, but it only catches the synchronous throw from `editor.dispose()`. In EcoSim this happens on every Edit > Undo from FlexDesk's MenuBar after a Monaco edit: `_activate` calls `_exit()`, which gives focus back to the Monaco textarea, and then `_fire()` re-renders and disposes the editors. VS Code avoids it with its own unhandledrejection handler, which ignores cancellation errors. Standalone Monaco has no such handler.

## Steps to reproduce

1. Focus a Monaco editor made with FlexDesk's editor factory.
2. Dispose its handle at once (within 50 ms).

## Expected

No unhandled rejection reaches the page: FlexDesk ignores Monaco's asynchronous CancellationError (name === 'Canceled' && message === 'Canceled'), for example with one window 'unhandledrejection' listener installed when Monaco loads (initMonaco) that calls preventDefault() for that error only. Any other rejection still surfaces. A regression test fails on today's main. Documented in a section headed "(0.17.6)" on docs/components/editor.md.
