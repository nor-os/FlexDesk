## Description

`installOverlayScrollbar` (src/ui/utils/overlay_scrollbar.js) appends a `.overlay-scrollbar` element with `.overlay-scrollbar-v` or `.overlay-scrollbar-h`, holding a `.track` and a `.thumb`, and positions them through top/height or left/width. No FlexDesk stylesheet has a rule for any of these classes (`grep -c overlay-scrollbar dist/flexdesk.css` prints 0). The bar is therefore `position: static`: it takes space in the scroll container, its height feeds back into the content height, and the container grows without limit. Until now this was hidden because EcoSim's own main_new.css carried the rules; EcoSim STORY-0105 removed them (FlexDesk owns generic UI), and EcoSim's Files navigator grew to millions of pixels and its paper Contents pane looked empty (EcoSim BUG-0040).

## Steps to reproduce

1. Call `installOverlayScrollbar(container, { orientation: 'vertical' })` on a container with overflowing content, with only flexdesk.css loaded.
2. Read the bar's computed `position`, and watch the container's `scrollHeight` across a few updates.

## Expected

flexdesk.css styles the overlay scrollbar: the bar is absolutely positioned at the container's right (vertical) or bottom (horizontal) edge, takes no layout space, is hidden until the container is hovered while it overflows, and its thumb can be dragged; colours come from FlexDesk tokens. Every FlexDesk component that calls installOverlayScrollbar gets this with no embedder CSS. A regression test fails without the fix. A docs section headed "(0.17.7)" describes it.

Filed from the EcoSim EPIC-0080 real-app check (EcoSim BUG-0040, caused by EcoSim STORY-0105). EcoSim's removed rules (EcoSim commit 9b646dcf, html/css/main_new.css) are a working reference: absolute bar 6px wide/high, opacity 0 until `[data-scrollable="1"]:hover`, z-index below managed windows, track and thumb rounded, thumb `pointer-events: auto`, min 30px. Check whether FlexDesk sets data-scrollable itself. Claimed for 0.17.7.
