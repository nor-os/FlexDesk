## Description

The tile menu (.tile-menu-dropdown: position:absolute; right:0; min-width:180px) is drawn inside the tile, which clips it. In a tile under about 220 px wide the menu starts 68 px left of the tile edge and its left part and labels are cut off; elementFromPoint at its top-left corner does not hit it.

## Steps to reproduce

1) A tile grid whose tiles are under 220 px wide (e.g. a 600 px window). 2) Click a tile's more_vert button.

## Expected

The menu is fully visible, drawn over neighbouring content and kept inside the window. A regression test fails without the fix.

### 2026-10-25T09:10Z · norman_agent (status: investigation -> closed)

Landed on main at b6d4dcc and released in FlexDesk 0.17.9 (3fe27a2, on npm). Independently reviewed and approved. Regression test: tests/tile_menu_unclipped.test.mjs. I ran it against the origin/main src and css, copied to the scratchpad: 8 of its 14 assertions fail there. On the bug-0043 branch all 14 pass. The test checks that an open menu sits on document.body (outside the tile), uses position fixed, has both edges inside the window and opens under the button. It also checks that the menu lines up right-edge with the button when there is room, that choosing an entry or pressing outside closes it and puts it back in the header, and that dispose with the menu open leaves no menu on the page.

Worktree: /home/norman/repos/FlexDesk-bug-0043. Fix is in src/tiles/tile_base.js. When opened, the menu moves to modalHost() or document.body, the same way showContextMenu does. It is placed by the existing ActionDropdown.position, which makes it fixed and keeps it inside the window. On close it goes back into the tile header. dispose() and a rebuilt header both close an open menu first.

One additive API change: ActionDropdown.position(trigger, menu, opts) now takes an optional third argument, { align: 'start' | 'end' }. The default is 'start', which behaves exactly as before. The tile menu passes 'end' so it keeps its old right-edge alignment.

The .tile-menu-dropdown z-index changed from --z-dropdown to --z-over-windows in both css/base.css and css/flexdesk.css, so the menu draws over a managed window that holds the grid. Docs: a (0.17.9) section in docs/components/tiles.md and one in docs/components/menus.md for the align option.

Not done: the menu does not move with the page if it scrolls while the menu is open. ActionDropdown has the same limitation today.

Minor review notes, left as they are:
- The open menu is now position:fixed on document.body, so if the tile grid or page scrolls while it is open the menu stays where it was instead of moving with the button, as the old absolute menu did. Nothing closes it on scroll or resize. ActionDropdown has the same limitation and the spec does not cover scrolling, so this does not block.
- The docs say the menu opens 'above it when there is more room there'. The code (ActionDropdown.position) opens it below whenever it fits there, and above only when it does not fit below but fits above. A small wording mismatch.
- When jsdom cannot be resolved (it is looked up through ../../Tables/web/node_modules), the test prints SKIPPED and exits 0. This follows the convention of the other 65 suites but can hide a regression. Verified: with jsdom present it fails 8 assertions with tile_base.js reverted, fails 1 with only action_dropdown.js reverted, and passes with the fix.

The full suite passed on the release commit (204 suites green).
