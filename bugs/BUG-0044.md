## Description

EcoSim BUG-0073 rethemes the accent by setting FlexDesk's accent tokens (--accent, --accent-hover, --accent-bright, --state-selected, --shadow-glow). Everything that reads a token follows, but these stay blue because they are literals in css/*.css (and dist/flexdesk.css):

1. The SliderField thumb (.twm-slider-field__input::-webkit-slider-thumb / ::-moz-range-thumb): #569cd6, and #6eb3e9 when active.
2. About 29 `rgba(0, 122, 204, a)` tints: DataTable selected rows and cells, filter chip on, autocomplete namespace and active item, .add-widget-btn, .tile.resizing, .tile-ghost, the .twm-leaf--focused inset shadow, the doc-outline active link, the canvas marquee, the flow-graph port dots, and others (tokens.css, base.css, flexdesk.css, overrides.css).
3. `var(--twm-dt-new-bg, rgba(0,122,204,0.22))`, where --twm-dt-new-bg is defined nowhere.
4. --state-selected and --shadow-glow are literals that do not derive from an accent token.

## Steps to reproduce

1. Load flexdesk.css and set `:root { --accent: magenta; --accent-hover: magenta; --accent-bright: magenta; --state-selected: magenta; --shadow-glow: magenta }`.
2. Look at a SliderField, a DataTable selection, an autocomplete's active item, a tile being resized.

## Expected

Every accent colour in FlexDesk's stylesheets is derived from an accent token (rgb(0,122,204) is --accent-bright; tints via color-mix of the token), so overriding the accent tokens rethemes all of them. With no override, every computed colour stays what it is today (the slider thumb may move to the nearest token-derived colour; document it). Whether --accent and --accent-bright become one token is out of scope (an owner decision). A regression test fails if any accent literal remains in the shipped CSS outside the token definitions.
