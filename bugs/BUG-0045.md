## Description

After BUG-0044 (0.17.10), setting the accent tokens rethemes #007acc, its tints and the light accent, but these accent-blue shades are still literals: the primary button hover (#1486cf, modal primary #1683c4), the flow-lanes ring (#1683c4, #5b9bd5, #0f6fa8, rgba(22,131,196)), the selected tile (#78b9ff, rgba(120,185,255)), the row cursor and snap preview (rgba(17,119,179)), #79b8f8, #9ecfff, the plot window and spinner (#4a90d9) and #268bd2. docs/concepts/styling.md lists them. None of them is an exact mix of an accent token, so deriving them would move their default colours.

## Steps to reproduce

Set `--accent`, `--accent-hover` and `--accent-bright` to magenta on :root and hover a primary button, select a tile, or look at the flow lanes.

## Expected

Owner decision: either derive these from the accent tokens too and accept small default colour shifts (as BUG-0044 did for #569cd6, about 1.5 ΔE), or settle on one accent (tokens.css: "Phase 5 will pick one") and fold the shades into it, or keep them as deliberate literals.

### 2026-10-25T15:20Z · norman_agent (status: investigation -> closed)

Landed on main as d0b1649 and a44ec36. Released in FlexDesk 0.17.11 (ca1dad1, on npm). Independently reviewed: one blocking finding was fixed in the review round, then approved. Regression test: tests/accent_tokens.test.mjs (93 assertions), plus tests/css_exports.test.mjs section 4.

Every remaining accent-blue shade now derives from the accent tokens: primary and modal hover, window bar, selected tile, row cursor, snap preview, plot window, spinner and flow lanes. Three new tokens: --accent-bright-hover, --accent-pressed and --accent-lightest. Default colours move by 0.2 to 4.1 ΔE (OKLab ×100), each listed in docs/concepts/styling.md '(0.17.11)' and in the CHANGELOG. --accent and --accent-bright stay two tokens.

Minor review notes:
- The table gives the selected tile ring's ΔE as 1.5. My own computation (8-bit, over #1e1e1e, OKLab x100) gets 1.58, which rounds to 1.6. Every other figure I spot-checked matches to one decimal: 0.4, 2.2, 1.3, 0.6, 0.3, 2.1, 4.1, 2.6, 3.2, 2.0, 1.2, 0.6, glow 1.7, row cursor 0.2. This is cosmetic only.
- Three blue literals are not covered by the docs' list of non-accent literals. Two are not named explicitly: .twm-autocomplete-field__namespace uses color #c7f1ff on an accent-tinted chip (line ~1700), and the flow-graph edge stroke fallback is #8fb4d8. The docs only vaguely cover the breadcrumb (#64b5f6, rgba(100,181,246)) and plot-series action (#6a9fd8, #8bb8ea) links as 'breadcrumb and plot-series links'. None of these are in BUG-0045's list, and they are arguably not accent. Consider naming the namespace chip text, since its background is derived from the accent.
- There are three new required tokens: --accent-bright-hover, --accent-pressed and --accent-lightest. An embedder who supplies its own token definitions instead of tokens.css (the docs allow this) would lose the primary hover, the window bar hover and active states, and the flow lanes ring unless it adds them. The 0.17.11 section does list the new tokens, but it does not say they are required when you bring your own tokens. Nothing was removed or renamed.

Before release, two of these notes were fixed in the docs and CHANGELOG: the selected tile ring's ΔE is 1.6, not 1.5, and the docs now say an embedder that supplies its own token definitions must also define the three new tokens. The full suite passed on the release commit (205 suites green).
