## Description

`css/flexdesk.css` (and `css/overrides.css`) set `animation: twm-tile-loading-spin 0.7s linear infinite` and `animation: data-table__spin 0.7s linear infinite`, but no stylesheet in FlexDesk defines `@keyframes twm-tile-loading-spin` or `@keyframes data-table__spin`. `git grep "@keyframes twm-tile-loading-spin\|@keyframes data-table__spin"` finds nothing. An embedder that loads only FlexDesk's CSS gets static spinners. EcoAgent still defines both keyframes in its own CSS, carried over from before its shell cutover (EcoAgent STORY-0028, `../EcoAgent/backlog/STORY-0028.md`).

## Steps to reproduce

1. Load only FlexDesk's `tokens.css`, `reset.css` and `flexdesk.css`.
2. Show a tile while its content is loading, or a DataTable while it fetches.

## Expected

The spinner turns.

## Actual

The spinner is drawn but does not move.

## Comments

### 2026-10-26T10:58Z · norman_agent (status: investigation -> testing)

Fixed on main in d87530c (dist rebuilt in 31de892). Not released: package.json is still 0.17.13.

`@keyframes twm-tile-loading-spin` and `@keyframes data-table__spin` are now defined, each a full turn at the 0.7s linear infinite the rules already name. Scanning every `animation` reference in the stylesheets against the keyframes that exist found two more with the same cause, `computing-spin` (the computing-status window) and `etl-spin` (the run-progress dialog); both are fixed too. The keyframes sit beside the rules in `css/flexdesk.css`, and in `css/base.css` and `css/overrides.css` where those carry the same rules.

`tests/stylesheet_keyframes.test.mjs` is a general guard: it parses the stylesheets and fails for any animation name without `@keyframes`, and checks the four spinners rotate a full turn. Docs: `docs/concepts/styling.md`, section "Spinners turn without keyframes of your own (0.17.14)" (provisional tag). An embedder that defined the same four names to work around this can delete them; if it keeps them, the later definition wins.

Three independent reviewers found no blockers; full suite 210 suites, none skipped. The checks read the CSS as text in jsdom: nobody watched a ring turn in a real browser, so please load `tokens.css`, `reset.css` and `flexdesk.css` and look at a loading tile once.

Not changed: the rings also turn under `prefers-reduced-motion`; the existing `spin` does too, and the sheet has no rule for it.
