## Description

`WindowManager.load()` (`src/tiling/wm.js`) passes the stored desktops blob to `DesktopManager.deserialize`, then canonicalizes and renders it, with no error handling. Invalid JSON is caught earlier (the Host logs `[host] bad JSON for state key desktops`), but valid JSON with the wrong structure throws. Examples are a split node whose `sizes` is not an array (`node.sizes.reduce is not a function`) or a tree missing expected fields. The throw happens during `createShell`, so the app never boots. It stays broken until the file is deleted by hand, and a truncated or hand-edited `desktops` file is enough to cause this.

EcoAgent hit this while dropping its old layout files (EcoAgent STORY-0036, `../EcoAgent/backlog/STORY-0036.md`). Its stopgap trial-loads the saved layout in a throwaway `WindowManager` before the shell restores it. That depends on FlexDesk internals (the panel-key router's private entries, `_persistTimer`) and renders every saved layout twice. EcoSim has the same exposure.

## Steps to reproduce

1. Save a layout, then edit `desktops` state so a split node has `"sizes": 5`. Alternatively, remove a desktop's `tree`.
2. Start an app with `createShell`.

## Expected

The broken layout is ignored with one warning that names the state key, and the shell opens with its default layout.

## Actual

`createShell` throws and the app does not boot.

### 2026-10-26T10:58Z · norman_agent (status: investigation -> testing)

Fixed on main in dfada54 (dist rebuilt in 31de892). Not released: package.json is still 0.17.13.

`DesktopManager.deserialize` and `TileTree.deserialize` now read the saved layout strictly and throw a `TypeError` that names the path and what was expected (`desktops[0].tree.root.sizes: expected 2 non-negative numbers, one per child, found 5`). `WindowManager.load()` catches around `deserialize` alone, warns once, and carries on as if nothing had been saved, so `createShell` opens the default layout. The warning is one string, `[wm] bad layout for state key desktops (opening the default layout): <cause>`, because a scoped LoggingService logger would otherwise keep only the second of several arguments. It goes to the shell's `logger` option (now passed through to the window manager), else `console`. The catch is deliberately narrow: a throw from canonicalize or render still reaches the embedder, since those only see a layout that was read.

The bad blob is left in the store, not deleted; the next layout change overwrites it, and until then each boot warns again.

Decision for norman: the loader is stricter than the old one. A split whose `sizes` is missing, the wrong length or non-numeric, an unknown `dir`, or a foreign-format blob (such as `{"ids":[...],"activeId":...}`) used to restore or load silently as the default, and is now discarded with a warning. None of those can come from `serialize()`, and the docs state the all-or-nothing rule, but it is a behaviour change. Say if you want it relaxed to only what actually threw.

For the release notes: `DESKTOPS_KEY` is now exported from `@flexdesk/wm` (the barrel re-exports `desktops.js`), and `TileTree.deserialize` takes an optional second argument; both additive.

Tests: `tests/saved_layout_unreadable.test.mjs` (many broken shapes, each giving the default layout and exactly one warning naming the key; valid layouts restore unchanged; an end-to-end `createShell` in jsdom; a real LoggingService, scoped and not). Docs: `docs/components/panels-and-desktops.md`, section "A saved layout that cannot be read (0.17.14)" (provisional tag). Three independent reviewers found one blocker in each of two rounds (the warning's argument shape, then the release tag); both are fixed. Full suite: 210 suites, none skipped.

Seen and left alone: the hosts' own "bad JSON" warning is multi-argument and loses its key through a scoped logger; a hostile `toString` object as a tab prop still throws, as before.

The recorded reporter is norman_agent, so the record stays with norman_agent in testing; reassign to norman to verify and close.

### 2026-10-31T02:34Z · norman_agent (status: testing -> closed)

Verified in a real embedder and closing. EcoAgent STORY-0061 (../EcoAgent/backlog/STORY-0061.md) removed EcoAgent's trial-load stopgap and now relies on 0.17.18 for this. Checked in EcoAgent in browser and windowed mode on fresh project copies:
- a corrupt `desktops` file (`{not json`) boots the default layout with one warning, `[host] bad JSON for state key desktops …`;
- a structurally broken one (`sizes: 5`) boots the default layout with one warning, `[wm] bad layout for state key desktops (opening the default layout): desktops[0].tree.root.sizes: expected 2 non-negative numbers, one per child, found 5`;
- a valid saved layout still restores.
