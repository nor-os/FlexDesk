## Description

`openForm`'s `setVisible(name, false)` (`src/ui/components/modal.js`, around line 325) moves a hidden control's `min` and `max` attributes into `el.dataset.twmMin` and `el.dataset.twmMax` so that showing the row gives back exactly what it had. Neither `twm-min` nor `twm-max` is in `DEFAULT_ALLOWED_DATASET_KEYS` (`src/core/state_guard_config.js`). Under a `StateGuardService` in `mode: 'strict'` built from `DEFAULT_STATE_GUARD_CONFIG`, hiding such a row throws, and in `warn` mode it logs a violation on every hide.

The documented promise (`docs/concepts/state-guard.md`, "The defaults cover FlexDesk's own keys (0.17.0)") is that the defaults include every data key FlexDesk's own widgets write, so the shell, dialogs and forms run clean under `strict`. `tests/state_guard_defaults.test.mjs` section 3 keeps that promise by scanning `src/` for literal keys, but this write names its key through a loop over `[['min', 'twmMin'], ['max', 'twmMax']]`, which none of its patterns match. Section 4 hides a required row, which writes `twmRequired` (listed), not a row with bounds.

Found by a reviewer while checking the BUG-0029 branch (BUG-0029 removes application keys from the same list; it does not touch this).

## Steps to reproduce

1. Build a `StateGuardService` with `{ ...DEFAULT_STATE_GUARD_CONFIG, mode: 'strict' }`.
2. `openForm({ title: 'Form', fields: [{ name: 'kind', label: 'Kind' }, { name: 'n', label: 'N', type: 'number', min: 1, max: 9 }], onFieldChange: (_n, _v, api) => { formApi = api; } })`.
3. `formApi.setVisible('n', false)`.

## Expected

The row hides, with no violation, as it does for a required row.

## Actual

`StateGuard blocked dataset:set on "data-twm-min" from .../src/ui/components/modal.js`. Reproduced in jsdom on main at 4ad5c82.

## Fix direction

List `twm-min` and `twm-max` in the "FlexDesk widgets" group of the defaults, and make the section 3 scan find keys written through a computed name (or add the two keys to its expected list with a comment saying why the scan cannot see them), so the next one is caught.
