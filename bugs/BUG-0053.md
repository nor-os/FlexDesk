## Description

Found reviewing EcoSim STORY-0121 (cells and dashboard tiles configured in ManagedWindows):

1. The constructor registers `_activeWindows.set(id, this)` and nothing deletes it on close: every closed window keeps its element, content and `onClose` closure (which captures its owner, e.g. a disposed editor) alive until the same id opens again, and `ManagedWindow.get(id)` returns the dead window. Saved geometry per id (`flexdesk.managedWindows.v1` in localStorage) grows with every new id.
2. Opening a window never moves focus into it, and closing it never returns focus to what opened it: a keyboard user who opens a config window with Enter stays in the page behind, and reaches the window's fields only by tabbing through the whole document.
3. `_onKeyDown` closes the top visible window on any Esc that reaches the document, wherever focus is: an Esc meant for an editor beside a non-modal window closes the window.

## Acceptance criteria

- [ ] A closed window is removed from the registry (and its content and callbacks released); `get(id)` answers null afterwards; reopening an id builds a fresh window. Saved geometry is bounded (e.g. a capped, least-recently-used set of ids, or opt-out per window for ephemeral ids). Existing geometry persistence for stable ids keeps working.
- [ ] An option (on by default where it is safe, e.g. `focusOnOpen`) moves focus to the first focusable element of the content when the window opens, and focus returns to the element that had it when the window closes (if still in the document).
- [ ] Esc closes a non-modal window only when focus is inside it; a modal window keeps closing on Esc as today.
- [ ] Tests; docs.
